# A 股本地炒股工具设计规格

## 目标

构建一个个人本地使用的 Web 炒股工具，第一版同时覆盖“看走势与持仓风控”和“选股雷达”。工具默认服务 A 股短线/波段交易，但架构预留其他市场和付费数据源扩展能力。

第一版不接入真实券商账户，不自动交易，不提供黑箱喊单。用户手动录入现金、持仓、买入均价和备注；系统用免费公开数据源拉取行情，展示接近东方财富体验的走势页面，并基于可解释策略给出仓位、止损、风险和候选股票建议。

## 范围

第一版包含：

- 本地 Web 应用，浏览器访问。
- A 股行情数据，优先使用 AkShare 免费公开数据源。
- 自选股与手动持仓管理。
- 总资产、现金、持仓市值、持仓盈亏、今日盈亏展示。
- 专业 K 线/分时图，支持分时、5 日、日 K、周 K、月 K。
- 常用技术指标，包括 MA、成交量、MACD、KDJ、RSI、BOLL。
- 趋势追强榜和超跌反弹榜。
- 固定风险仓位、分数凯利仓位、止损线、加仓上限、超配提醒。
- 操作建议折叠展示，并解释信号来源。

第一版不包含：

- 券商账户登录或自动读取持仓。
- 自动下单。
- 多用户账号、权限、订阅、审计。
- 实时盘口 Level-2、逐笔成交等高频交易终端能力。
- 未经回测和解释的机器学习荐股黑箱。

## 产品结构

应用包含四个顶层标签页：

1. 主页
2. 选股雷达
3. 策略回看
4. 设置

### 主页

主页是日常决策入口，只放账户、当前股票走势、持仓盈亏和风控建议，不放选股榜单。

顶部显示：

- 总资产
- 可用现金
- 持仓市值
- 持仓盈亏
- 今日盈亏
- 数据源状态和更新时间

左侧显示持仓和自选列表。每只股票展示名称、代码、涨跌幅、是否持仓、持仓数量和浮动盈亏。用户可以添加股票、录入持仓、编辑现金。

中间是走势区域。正式实现使用专业 K 线图表库，目标体验接近东方财富，支持：

- 分时、5 日、日 K、周 K、月 K 切换
- 蜡烛图、成交量副图
- MA5、MA10、MA20、MA60
- MACD、KDJ、RSI、BOLL 切换
- 十字光标、缩放、拖拽
- 成本线、止损线、建议加仓/减仓点位标记
- 复权类型配置

右侧显示：

- 保守风控建议
- 信号来源解释
- 折叠的操作建议

默认只显示保守风控建议。买入、加仓、减仓、清仓等操作建议必须由用户主动展开，并且必须说明触发依据。

### 选股雷达

选股雷达独立于主页，负责发现候选股票。它不直接决定交易，用户点击候选后回到主页查看走势、账户和仓位建议。

左侧是筛选条件：

- 市场范围：沪深 A 股
- 周期：短线/波段
- 行业或概念
- 成交额和流动性阈值
- 风险过滤开关

右侧分两套榜单：

- 趋势追强榜
- 超跌反弹榜

每条候选显示股票、代码、评分、主要原因、风险状态和“看走势”入口。

### 策略回看

第一版保留入口，用于后续复盘策略表现。初始版本可以展示历史榜单、候选后续表现、建议命中率和交易备注，不作为 MVP 的核心复杂模块。

### 设置

设置页配置：

- 数据源优先级
- 风险参数，例如单笔最大风险、分数凯利折扣、默认止损参数
- 指标参数，例如均线周期、ATR 周期
- 数据刷新频率
- 本地数据库备份与导入导出

## 数据层

第一版使用免费公开数据源，优先 AkShare。系统必须通过数据适配器访问外部数据，前端和策略模块不直接依赖 AkShare 原始字段。后续可以加入 Tushare、聚宽、米筐、Wind、Choice 或券商 API 适配器。

所有外部数据进入系统前先标准化，并写入本地 SQLite。每条行情和计算结果必须带更新时间。

核心数据实体：

- `Stock`: 代码、名称、市场、行业、上市日期、是否 ST、是否停牌、退市风险标记。
- `PriceBar`: 股票代码、周期、时间、开盘、最高、最低、收盘、成交量、成交额、换手率、复权类型。
- `IntradayBar`: 股票代码、时间、价格、成交量、成交额。
- `AccountSnapshot`: 日期、现金、持仓市值、总资产、当日盈亏。
- `Position`: 股票代码、持仓数量、买入均价、手动备注、更新时间。
- `IndicatorValue`: 股票代码、周期、指标名、参数、时间、值。
- `ScreenerResult`: 榜单类型、股票代码、评分、评分拆解、风险过滤结果、生成时间。
- `RiskAdvice`: 股票代码、建议仓位区间、最大可买金额、止损价、单票风险、建议文本、生成时间。

## 选股策略

所有策略输出必须可解释、可回看、可禁用。趋势追强和超跌反弹分开评分，不混合排序。

### 趋势追强榜

目标是找正在走强的行业龙头和趋势候选。

评分因子：

- 行业或概念强度：板块涨幅、板块内上涨比例、龙头集中度。
- 个股相对强度：近 5、10、20 日涨幅相对市场和行业排名。
- 量价趋势：放量突破、均线多头、价格站上关键均线。
- 短线热度：涨停、连板、成交额、换手率。
- 风险过滤：ST、停牌、退市风险、流动性不足、连续一字板不可交易。

### 超跌反弹榜

目标是找跌幅充分但出现企稳迹象的候选。

评分因子：

- 回撤幅度：近 20、60 日从高点回撤。
- 企稳信号：缩量、止跌阳线、放量反包、接近支撑位。
- 乖离程度：偏离 MA20、MA60 或 BOLL 下轨。
- 情绪修复：行业不再继续走弱，跌停减少，成交恢复。
- 风险过滤：避免把基本面恶化、流动性枯竭、退市风险误判成超跌机会。

## 仓位与风控

默认使用“固定风险 + 分数凯利”的保守组合。系统不使用满凯利作为默认建议，因为凯利公式依赖可靠胜率和盈亏比，实盘估计误差会显著放大风险。

每只股票建议仓位由三层限制取最小值：

1. 单笔风险上限，例如账户总资产的 0.5% 到 2%。
2. 止损距离仓位：`可承受亏损 / (当前价 - 止损价)`。
3. 分数凯利上限：根据历史策略胜率和盈亏比估算，再乘 0.25 或 0.5。

若胜率或盈亏比样本不足，凯利仓位不启用，只给固定风险仓位。

风控输出包括：

- 建议仓位区间
- 最大可买金额
- 当前持仓是否超配
- 止损价
- 止损触发后的减仓或清仓建议
- 单票最大亏损
- 账户总风险暴露
- 操作建议解释

## 技术架构

推荐技术栈：

- 前端：React、TypeScript、Vite
- UI：Tailwind CSS 与轻量组件系统
- 图表：TradingView Lightweight Charts 或同级别专业 K 线库
- 后端：Python FastAPI
- 数据库：SQLite
- 数据源：AkShare
- 调度：本地后台刷新任务

本地运行方式：

1. 启动后端服务。
2. 后端初始化 SQLite。
3. 前端访问本地 API。
4. 用户在浏览器打开本地地址。
5. 用户手动刷新数据，或每日盘后由本地任务刷新。

## 模块划分

### MarketData

负责从 AkShare 获取并标准化 A 股基础信息、实时行情、历史 K 线、分时、指数、板块和行业数据。

### Portfolio

负责现金、持仓、买入均价、手动调整记录、持仓盈亏、总资产和今日盈亏。

### Indicators

负责 MA、MACD、KDJ、RSI、BOLL、ATR、回撤、相对强度、成交量变化等通用指标。

### Screener

负责生成趋势追强榜和超跌反弹榜。每条结果必须保存评分拆解和风险过滤结果。

### RiskAdvisor

负责固定风险仓位、分数凯利、止损线、加仓上限、超配提醒和操作建议解释。

### Frontend

负责主页、选股雷达、策略回看和设置四个标签页。前端只消费标准化 API，不直接调用数据源。

- `GET /api/portfolio/positions`

- `GET /api/screener/results?type=trend`
- `GET /api/screener/results?type=rebound`

## 错误处理

- 数据源失败时显示明确状态，不用过期数据伪装成实时建议。
- 行情、榜单、风控建议都显示 `last_updated`。
- 选股榜单显示生成时间和使用的数据日期。
- 若数据缺失，禁用相关建议，并说明缺失字段。
- 若股票触发 ST、停牌、退市风险或流动性不足，标红并禁用操作建议。
- 若凯利输入样本不足，禁用凯利，仅显示固定风险仓位。

## 测试计划

- 指标计算单元测试：MA、MACD、KDJ、RSI、BOLL、ATR。
- 仓位公式单元测试：固定风险、止损距离、分数凯利、取最小限制。
- 策略评分样例测试：趋势追强和超跌反弹各准备固定样例。
- 数据适配器测试：AkShare 字段标准化、缺失字段处理、更新时间处理。
- API 测试：持仓录入、现金更新、行情查询、榜单生成、风控建议。
- 前端验证：主页资产卡片、持仓列表、K 线渲染、选股雷达、建议抽屉。
- 浏览器验证：桌面宽屏和常见笔记本尺寸下无重叠、图表非空、交互可用。

## 风险与边界

本工具是个人决策辅助工具，不保证收益，不替代独立判断。所有策略都必须可解释、可回看、可禁用。免费公开数据源可能存在延迟、限频、字段变化和临时不可用，系统必须暴露数据状态，并在数据不可靠时降低或禁用建议。

## 参考依据

- AkShare 数据字典覆盖 A 股实时、历史、分时、指数和板块等免费公开数据接口。
- A 股研究中动量和反转效应都存在，但会随市场状态变化，必须拆分策略、做风险过滤，并保留回看能力。
- 凯利公式在交易中适合做仓位上限参考，默认使用分数凯利以降低胜率和盈亏比估计误差带来的风险。
