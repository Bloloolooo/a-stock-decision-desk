# A 股本地炒股工具实施计划

## 目标

基于已确认的设计规格，先交付一个能在本机运行的 Web MVP。第一轮实现以稳定工作流为主：主页账户概览、持仓录入、专业图表容器、风控建议、选股雷达页面和后端模块边界。免费行情源 AkShare 作为数据适配器接入，但前端和核心算法不直接依赖外部字段。

## 阶段 1：项目骨架

- 创建全栈项目结构：
  - `backend/`: FastAPI、SQLite、业务模块、测试。
  - `frontend/`: React、TypeScript、Vite、页面和组件。
  - `docs/`: 设计与实施文档。
- 添加本地运行说明。
- 添加基础配置：
  - Python 依赖文件。
  - Node/Vite 配置。
  - TypeScript 配置。
  - 基础 lint/test 命令。

验收标准：

- 后端能启动并返回健康检查。
- 前端能启动并访问主页。
- README 说明本地启动方式。

## 阶段 2：后端核心模型与 API

- 建立 SQLite 数据库初始化逻辑。
- 实现核心数据表：
  - 股票基础信息。
  - 行情 K 线。
  - 账户快照。
  - 持仓。
  - 选股结果。
  - 风控建议。
- 实现 API：
  - `GET /api/health`
  - `GET /api/portfolio/summary`
  - `GET /api/portfolio/positions`
  - `POST /api/portfolio/positions`
  - `POST /api/portfolio/cash`
  - `GET /api/market/bars/{symbol}`
  - `GET /api/screener/results`
  - `GET /api/risk/advice/{symbol}`

验收标准：

- 可以录入现金和持仓。
- 可以读取账户汇总和持仓列表。
- 没有外部行情时也能返回可控的示例数据，方便前端开发。

## 阶段 3：指标与风控

- 实现指标计算：
  - MA
  - MACD
  - RSI
  - BOLL
  - 回撤
  - 相对强度计算接口，第一轮基于近 5、10、20 日涨跌幅排名实现
- 实现风控计算：
  - 总资产、持仓市值、浮动盈亏。
  - 单笔风险上限。
  - 止损距离仓位。
  - 分数凯利上限。
  - 建议仓位区间。
  - 最大可买金额。
  - 超配提醒。

验收标准：

- 样例持仓能生成清晰的风控建议。
- 凯利输入样本不足时自动降级为固定风险仓位。
- 指标和仓位公式有单元测试。

## 阶段 4：数据适配器

- 实现 `MarketDataProvider` 抽象接口。
- 实现 `SampleDataProvider`，用于离线和测试。
- 实现 `AkShareProvider`：
  - 股票基础信息。
  - 历史日 K。
  - 分时数据。
  - 板块或行业数据。
- 所有数据进入系统前标准化。
- 外部数据失败时返回明确错误状态。

验收标准：

- 没有网络或 AkShare 不可用时，应用仍可使用示例数据。
- AkShare 字段变化不会直接影响前端。
- 每条行情结果带更新时间。

## 阶段 5：前端主页

- 实现四个顶层标签：
  - 主页
  - 选股雷达
  - 策略回看
  - 设置
- 主页包含：
  - 总资产、现金、持仓市值、持仓盈亏、今日盈亏。
  - 持仓/自选列表。
  - K 线图表区域。
  - 分时、5 日、日 K、周 K、月 K切换。
  - 风控建议、信号来源、操作建议抽屉。
- 图表优先使用 `lightweight-charts`。

验收标准：

- 页面结构接近已确认 V2 草图。
- 资产和持仓数据来自后端 API。
- 图表非空，支持基本缩放和十字光标。
- 页面在常见笔记本宽度下无明显重叠。

## 阶段 6：选股雷达

- 实现趋势追强榜和超跌反弹榜页面。
- 实现筛选条件 UI：
  - 市场。
  - 周期。
  - 行业。
  - 成交额阈值。
  - 风险过滤。
- 每条候选展示：
  - 股票名称和代码。
  - 评分。
  - 主要原因。
  - 风险状态。
  - 看走势入口。

验收标准：

- 榜单与主页分离。
- 点击候选能切回主页并显示对应股票。
- 榜单结果可解释，不直接喊单。

## 阶段 7：验证与打磨

- 后端测试：
  - 指标计算。
  - 风控公式。
  - 持仓 API。
  - 数据适配器标准化。
- 前端验证：
  - 主页渲染。
  - 选股雷达渲染。
  - 图表非空。
  - 操作建议抽屉。
- 浏览器检查：
  - 桌面宽屏。
  - 笔记本宽度。
  - 图表与文本不重叠。

验收标准：

- 后端测试通过。
- 前端构建通过。
- 本地页面可访问。
- README 中有明确启动步骤。

## 第一轮实现顺序

1. 搭建后端 FastAPI 与前端 Vite 项目。
2. 实现示例数据和 SQLite 基础表。
3. 实现持仓录入、账户汇总和风险建议 API。
4. 实现主页 UI 和图表容器。
5. 实现选股雷达静态到动态数据。
6. 接入 AkShare 作为可选数据源。
7. 补测试和 README。

## 重要边界

- 第一版不自动下单。
- 第一版不接券商。
- 第一版不做实时机器学习训练。
- 所有建议必须显示数据时间和解释。
- 外部数据失败时，必须让用户知道当前建议是否可用。
